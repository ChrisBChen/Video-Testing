# Dr. Pip's Science Hypotheticals — Episode 1: *What If All Friction Disappeared for 30 Seconds?*

A 42-second, 1080×1920, 30 fps pixel-art science explainer for TikTok / Reels / Shorts, **generated entirely from code**: every frame is a pure function of the frame number (React + Remotion + Canvas 2D), so renders are deterministic and reproducible. Narration, music and sound effects are also generated by scripts in this repo.

**Deliverables**

| File | What it is |
|---|---|
| `final_video.mp4` | The finished video (H.264 High, yuv420p, 1080×1920, 30 fps, AAC 48 kHz stereo, 42.0 s, loops seamlessly) |
| `script.md` | Final narration, on-screen text and sound design |
| `storyboard.md` | Hook options, timecoded shot list, camera and transition notes |
| `science_notes.md` | The exact physical interpretation, claim-by-claim justification, simplifications, references |
| `src/` | Animation source (see below) |
| `tools/` | Audio generator, caption timing, QA helpers |

## Run it

```bash
npm install                      # Remotion 4, React 18, TypeScript
npm run studio                   # live preview & scrubbing
npm run render                   # -> final_video.mp4 (about 2 minutes on 4 cores)
npm run typecheck
```

`public/audio/mix.wav` and `src/data/captions.json` are committed, so rendering needs nothing else.
If Remotion cannot download its own browser (offline / sandboxed machines), point it at any Chromium:
`REMOTION_BROWSER=/path/to/chrome npm run render -- --browser-executable=$REMOTION_BROWSER`.

### Rebuild the soundtrack and captions (optional)

```bash
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
npm run voice                    # downloads the Piper voice (en_US-ryan-high) into audio_cache/
PIPER_PY=$(which python) PIPER_MODEL=audio_cache/en_US-ryan-high.onnx python3 tools/build_audio.py
```

`tools/build_audio.py` reads `src/data/script.json` and `src/data/timeline.json` and
1. synthesises each narration line with Piper TTS and places it on the timeline,
2. measures real pauses in the speech and pins phrase boundaries to them, then writes word-timed captions to `src/data/captions.json`,
3. synthesises ~20 kinds of sound effects (numpy) at the cue times listed in `script.json`,
4. synthesises the chiptune score (with automation, e.g. the dramatic cut to silence before the WHAM) and ducks it under the voice,
5. mixes, soft-clips and loudness-normalises to −14 LUFS with ffmpeg → `public/audio/mix.wav`.

Only audio that is actually in the render is claimed: narration (Piper TTS), original synthesized music, synthesized SFX, and burned-in word-timed captions. All audio is generated locally; no third-party audio assets are used.

## How the code is organised

```
src/
  index.ts, Root.tsx, Video.tsx   Remotion entry: one 1080x1920 composition, one pixel canvas, captions + audio
  data/
    timeline.json                 scene start/duration, transitions, friction-return frame  <- retime here
    script.json                   narration lines + start times, SFX cues, music settings
    captions.json                 generated word timings (frames)
  engine/                         reusable across episodes
    palette.ts                    one shared ~30-colour palette (plus a few one-off tints)
    px.ts                         pixel primitives: rect, Bresenham line, disc, panel, bitmap text, outlined rotatable sprites
    scientist.ts                  Dr. Pip: parametric pose (limbs by 2-bone IK, lean, mouth/eyes/brows, rotation), gait() & idle()
    physics.ts                    deterministic helpers: seeded RNG, ballistic/bounce, debris bursts, camera shake, IK
    ease.ts                       easings, keyframe tracks, springs
    timeline.ts                   typed access to timeline.json
    render.ts                     scene dispatcher + pixel-block transition compositor (dissolve / iris / wipe)
    hud.ts, ui.ts                 experiment clock HUD, icon chips
  components/Captions.tsx         karaoke captions in the platform-safe band
  art/                            episode art: lab, town, vehicles, props
  scenes/                         hook, setup, walk, cars, grip, payoff, epilogue  (one pure function each)
tools/
  build_audio.py                  voice + captions + SFX + music + mix
  fetch_voice.sh                  downloads the TTS voice
  stills.sh, contact.py           render stills and build contact sheets for QA
```

### Design rules (these make a future episode cheap)

* **Pixel-perfect world**: scenes draw on a 90×160 grid that is scaled 12× with nearest-neighbour; sprites are drawn with a 1-px outline and rotated by nearest-neighbour sampling so rotation stays crisp. The HUD and text are on the finer 180×320 grid.
* **Determinism**: no `Math.random`, no wall-clock, no stateful simulation. Randomness is seeded; physics is closed-form in time (`kin`, `bounceY`, `burst`) so any frame can be rendered alone and in any order. Slow-motion is a pure time-warp function (`warp()` in `payoff.ts`).
* **Scene = function of local frame**: `(g, t, f) => void`; the dispatcher handles transitions by drawing the outgoing scene underneath a block mask.
* **Safe areas**: captions are at y 1290–1446 px, the HUD at y ≈ 200 px, and action sits between; nothing essential is in the top 12 % or bottom 22 %.

### Making another episode

1. Copy `src/scenes/*` as a starting point; write new scenes against `engine/` (`drawScientist`, `gait`, `drawHud`, `chip`, …) and add them to `src/scenes/index.ts`.
2. Edit `src/data/timeline.json` (scene ids, frame ranges, transitions, `returnFrame`) and `src/data/script.json` (narration, SFX cues).
3. `python3 tools/build_audio.py`, then `npm run render`.

Dr. Pip, the HUD clock, the mug that knows what's about to happen, and the "flash into frame 0" loop are the recurring series devices.

## Verified properties of `final_video.mp4`

Checked with `ffprobe`/`ffmpeg`: H.264 High profile, yuv420p, 1080×1920 (9:16), 30 fps, 1260 frames, 42.0 s, AAC stereo audio present, integrated loudness −14.0 LUFS, true peak ≈ −1.8 dBFS, no black or frozen segments, and the last frame matches the first frame (loop). See `science_notes.md` for scientific scope and caveats.
